# LostPlanet Tier 3 Deep Research

## Objective

Research Tier 3 nodes with a **distinctiveness-first audit**.

This tier contains long-tail, highly specific, or subcomponent nodes that are most at risk of generating duplicate filler if researched with the same template as Tier 1 and Tier 2.

For Tier 3, the first question is **not** “what is the economic logic?”

The first question is:

`Does this node deserve unique additive content, or should it inherit from a parent / cluster / higher-level system node?`

## Non-Duplication Rule

Tier 3 exists specifically to prevent duplication.

Do **not** produce unique fields for a Tier 3 node unless you can show that the node adds meaningfully distinct information beyond:

- its parent phenomenon
- its sector cluster
- its direct human or planetary impacts already visible elsewhere
- a nearby higher-order node that already captures the same mechanism

If the node is not distinct enough, mark it as `inherit` and explain from which parent or cluster it should inherit.

## Research Workflow

For each Tier 3 node:

1. Identify the nearest parent, cluster, or higher-level system node.
2. Decide whether the node is:
   - `unique`
   - `inherit`
   - `minimal`
3. Only if it is `unique`, provide additive fields.

Definitions:

- `unique`: deserves its own additive logic because it changes burden distribution, threshold logic, or intervention design in a meaningfully different way
- `inherit`: should reuse its parent node’s additive logic to avoid duplication
- `minimal`: deserves at most a short note, not a full five-field layer

## Product Structure To Support

Tier 3 should still map back to the same product slots, but **only where warranted**:

- `Hidden Cost`
- `Who Pays`
- `Physical Limit`
- `Default Driver`
- `System Levers`

If the node does not justify unique content, do not force those fields.

## Output Format Per Node

For each node, return:

### `[node_id]`

- `Distinctiveness verdict:` `unique`, `inherit`, or `minimal`
- `Nearest parent or cluster:` 1 line
- `Why:` 1 to 2 sentences

If verdict is `inherit`:

- `Recommended inheritance source:` one node or cluster
- `Why this avoids duplication:` 1 sentence

If verdict is `minimal`:

- `Minimal note:` max 2 sentences

If verdict is `unique`:

- `Research confidence:` `High`, `Medium`, or `Emerging`
- `Hidden Cost:` max 2 sentences
- `Why this is not duplicative:` 1 sentence
- `Who Pays:` max 2 sentences
- `Why this is not duplicative:` 1 sentence
- `Physical Limit:` max 2 sentences
- `Why this is not duplicative:` 1 sentence
- `Default Driver:` max 2 sentences
- `Why this belongs in What Can Be Done:` 1 sentence
- `System Levers:` 3 to 5 flat bullets
- `Key evidence:` 3 to 6 bullets with source, date if available, factual takeaway, URL

## Research Quality Bar

The best Tier 3 output will usually recommend inheritance or minimal treatment unless the node truly changes:

- burden distribution
- threshold logic
- policy design
- infrastructure response
- system leverage

Do not manufacture uniqueness where there is none.
